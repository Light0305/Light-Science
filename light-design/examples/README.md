# examples 说明

本目录只放**结构示意**，不放真实运行产物：没有真实设计书全文、
没有评审包与评审记录原件。想看真实跑通的形态，请用自己的一张
定版想法卡按 [../README.md](../README.md) 的命令走一遍。

## 一个方向项目（`init` 产物）的目录形态

```text
my-design/                          # 一个研究方向 = 一个项目目录
├── project.yaml                    # 方向名与项目元信息
├── index.yaml / index.md           # 项目级索引（命令自动维护）
├── design-stage/
│   ├── DESIGN_REPORT.md            # 唯一权威文档：入口校验/设计索引/定版决议/偏离汇总（report 刷新）
│   └── intake_log.md               # 入口校验与打回记录（每次消费交接逐条留痕，不许删）
├── designs/<design_id>/            # 一想法一份设计（slug_hash6）
│   ├── design.yaml                 # 设计书结构化本体（权威源，十一区，字段总表见 README）
│   └── design.md                   # 人读版渲染（由 design.yaml 生成，不许手改）
├── review/<design_id>/             # 定版评审包与记录（review prepare/record 落盘）
│   ├── review_packet.md            # 自包含评审包：全文交给异家族模型/专家评审
│   ├── review_checklist.yaml       # 评审者逐项填写版
│   └── review_record.json          # 评审记录存根（含收据 id）
└── exports/<design_id>/            # 交接四件套（仅 frozen 设计可导出）
    ├── experiment_brief.md         # 运行清单（依赖拓扑序）+ 判读 + 熔断，Experiment 照单执行
    ├── design_card.json            # 设计书结构化全量 JSON 投影
    ├── expected_registry.jsonl     # 预期登记表：每 run 一行，供 Analysis 事后逐条对账
    └── reproducibility.md          # 种子/环境/数据版本/调参对等/冻结锚点
```

## 端到端演示（脱敏摘要）

开发期曾以 light-idea 演示的一张真实想法卡（视频分析方向，
执行级规格六项齐全）为输入做过一次完整演示，全过程结论如下，
原始产物属开发档案、不在本仓库：

- **承接前提如实标注**：该卡在 Idea 侧未定版（跨模型复核硬门
  未过），演示承接的是「规格完备但未定版」的卡——属演示安排，
  不冒充正式定版交接；Design 的产品口径只消费定版卡。
- 主设计（完整级）：入口承接 6/6（其中四项在设计中展开深化）→
  设计书补全（主张 2 条 + 反主张 3 条、运行清单 10 条且处理组
  全部对照先行、消融矩阵 6 行逐行预写判读、效度四分法 9 项
  逐项三态、功效替代口径给出种子/重复/评估集推导与敏感性
  范围、双货币预算 + 熔断线 4 条）→ 校验零错误 → 推进
  reviewed 通过 → 生成自包含评审包。
- 定版一步被如实拦下：演示环境只有单一模型家族，评审走
  REVIEW_UNAVAILABLE 显式降级落盘，frozen 被定版门拦截
  （逐条点名未过项），交接导出亦被拒。**演示终点 = reviewed
  + 评审包就绪**——不定版、不停工、不伪造收据；多模型环境中
  把评审包交给异家族模型/专家、回填判定即可定版并导出四件套。
- 打回流程演示：构造缺两项的交接变体 → new 当场列打回清单 →
  推进 reviewed 被承接门逐项点名拦下 → 正式打回（returned）
  → 上游补发完整交接件后回补（逐项重新承接并置 resolved、
  往返记录保留）→ 回到 draft，全流程走通。
- 极简级演示：一份公开基准上的判别实验小设计，底线六件
  （主张/判读三向/对照/重复层级/可见性声明/熔断线）齐全、
  校验通过，渲染带「极简设计 · 不承载确认性结论」标注；
  按口径不评审、不冻结。
