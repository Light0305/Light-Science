# light-patent

> Light-Science 子技能：出口层扩展位（拍板 LD-02，与 light-review
> 之后并列的权利固化出口，不进十阶段主流水线）。设计依据：
> `12-patent/` 学习三件（census 27 条、deep-read 16 单元、
> learning-notes 的 P0–P7 坐标与 LP 硬约束）与第二轮拍板第四批
> Q1–Q10。规范锚点：专利法（2020 年修正）、专利法实施细则
> （2023 年修订）、专利审查指南（含局令第 84 号修改，2026-01-01
> 施行）。引用实施细则条号必须带版本年份。
>
> **版本：v1.0（2026-10-21 夜班新建）**。§1–§13 为已实现规程；
> 演示见 `examples/demo-fullrun/`（终点 responded，含模拟递交与
> 模拟审查意见，报告内逐项标注）。

## §1 定位与边界

- 做什么：把已成型的技术方案转成可审查、可答辩、可管理的中国
  发明专利申请资产：公开审计、交底、查新、撰写、审核、答复、
  静态台账，旁路带政策雷达 lite。
- 客体与法域（Q1/Q2）：v1 只做**发明专利**、只做**中国**。
  实用新型与外观登记 v1.1；PCT 只在台账给优先权 12 个月时间窗
  与单一性提示，不写外国申请文件。
- 法律结论口径（Q4）：一切新颖性/创造性/可实施性结论均为草案
  级。交付物固定携带一级声明「草案，需专利代理师复核」；查新
  结论、worth-it 判断等初筛产物再加二级声明「只作初筛底稿、
  不作法律意见」。不作授权可能性承诺。允许给 worth-it 结论
  （建议申请/收窄申请/放弃），但必须附证据账，证据账为空不许
  落结论。
- 协作形态（Q8）：发明人自助成稿后交专利代理师复核。会稿问题
  清单只做单向导出件（oa/meeting_questions.md），不建会稿状态机。
- 数据与隐私（Q9）：未申请案件材料只存本地项目目录，本包无
  任何上传动作；查新检索词按最小披露生成（见 §6）；身份证件号
  等身份信息不落本包任何文件（LP-12）。

## §3 硬约束 LP-01 至 LP-12（定版）

- LP-01 不编造：专利号、公开日、申请人、法律条文号、审查结论
  一律实查；查不到标「待复核」，著录未核验条目不得作决定性
  依据（不得锁 D1）。
- LP-02 证据接地：每条权要实质特征必须映射到源材料锚点
  （P/E/F/C 源 ID 或文献锚点）；支持状态四值（explicit 明确
  记载 / inherent 固有公开 / needs-confirmation 待确认 /
  unsupported 无支持），unsupported 特征禁止进入正式权要。
- LP-03 缺口显式：缺失信息用占位符（待补充：…）呈现并逐条
  登记进缺口清单；禁止用推测填缺口。
- LP-04 正文洁净：申请文件正文只含技术披露；源 ID、支持状态、
  查新过程、工具名、策略评论只进工作副本，申报副本由工作副本
  机械剥离生成并经洁净检查与 diff 留痕（strip 命令）。
- LP-05 D1 纪律：查新必须锁定最接近现有技术并写选定理由；
  区别特征全案统一编号 F1、F2…；证据级别（摘要级/全文级）随
  结论标注，摘要级判断不得表述为全文结论；禁止假 D1。
- LP-06 失败分型：检索渠道失败、检索成功 0 条、检索成功但池
  空未评估，三态严格分开记录；禁止把渠道失败写成「无现有
  技术」。
- LP-07 法律结论降级：见 §1 分级声明；交付分级只有
  deliverable_draft 与 incomplete_draft 两档，禁止自称可申报。
- LP-08 第 33 条红线：答复与修订的每条修改必须指出在原说明书
  和权利要求书中的出处指针并附原文摘录，无出处不许落账。
- LP-09 公开状态前置：未完成 P0 公开审计不得进入挖掘与撰写；
  已公开且非宽限情形时，交付前显著告知「论文即现有技术」的
  后果（blocked 字段点名）。
- LP-10 规范锚点现行版：撰写口径锚定现行文本（2020 年专利法、
  2023 年实施细则、审查指南含 84 号令）；指南再修订走政策雷达
  增量登记，不靠模型记忆改口径；引实施细则条号带版本年。
- LP-11 审核双层缺一不可：确定性脚本检查 + 红队两队（权要
  红队、整包红队）；检查报告自报覆盖与未查项；任一缺位或
  ERROR 未清，交付等级只许 incomplete draft。
- LP-12 身份类信息不落猜测：申请人、发明人、优先权、费减等
  请求书字段未知即写「待填写/需确认」；发明人只记自然人姓名，
  身份信息线下核对、不进本包文件；敏感字段名（身份证号等）
  出现在当事人数据中即校验报错。

## §4 P0 公开状态审计（先于一切撰写）

决策表（audit 命令机械判定，只对已登记事实作答；无登记且未
具名确认穷尽登记时结论为 unknown，不许推进）：

| 情形 | 结论 | 处置 |
|---|---|---|
| 无任何在先公开且具名确认 | clear | 先申请后公开；论文、预印本、代码公开一律排在申请日之后 |
| 最早公开在申请（计划）日前 6 个月内且属第 24 条四情形之一 | grace_possible | 申请时声明，并于申请日起 2 个月内提交证明文件（实施细则（2023 年修订）第 33 条） |
| 已公开且非宽限情形（含超窗、预印本公开） | blocked_prior_disclosure | blocked 字段点名；只能围绕未公开的改进点重新立项 |
| 公开状态未知 | unknown | 补齐登记后再审 |

专利法（2020 年修正）第 24 条四情形：国家紧急/非常情况为公共
利益目的首次公开；中国政府主办或承认的国际展览会首次展出；
在规定的学术会议或技术会议上首次发表；他人未经申请人同意而
泄露。注意：一般国际学术会议（CVPR、NeurIPS 等）通常不属于
「规定的学术会议」，arXiv 等预印本公开不属于四情形——宽限期
不是已公开成果的通用解法。同时审计权属与发明人构成（职务
发明、合作成果），发明人资格口径见 §10 的 84 号令 4.1.2 引文。

## §5 P1 交底挖掘（四路输入，Q5）

- 四路并列：论文（light-literature 四件套为第一路，锚点与文献
  锚点同构）、代码仓、实验记录、口头交底。口头交底只作补充
  输入，其单独支撑的特征支持状态至多 needs-confirmation。
- 源图谱先行：动笔前给源材料编稳定锚点（P 文本块 / E 公式 /
  F 图 / C 代码）。代码仓走 scan-code 机械盘点：遍历源文件、
  按子系统分组逐文件落 C 锚点；盘点只登记不判发明点，发明点
  由候选表回锚。
- 候选表八字段：技术问题、技术手段、技术效果、证据支持、
  权利要求类别、披露缺口、风险。默认只选最强一案成案；多案先
  出布局说明再问用户，不并案硬写。
- 交底书结构：问题—手段—效果 + 系统框图/流程要点 + 关键参数
  与公式 + 实施例与可替换方案；AI 类方案另须挖齐 §10 的充分
  公开三组材料（模块层级连接、训练步骤参数、输入输出设置）。

## §6 P2 检索查新与渠道层（Q3/Q9）

- 两轮召回：第一轮手段短语，第二轮分类号邻域（从第一轮结果
  抽 IPC/LOC 高频号加手段词）。两轮均须登记轮次、渠道、检索
  式、结果分型与命中，入 novelty/search_log.jsonl（只增不改）。
- 渠道层可替换：渠道登记表（channels 命令）为一等工件，每条
  含可审计性/可复现性与披露考量字段。官方公开渠道人工辅助为
  默认；CNIPA 公布站自动化抓取默认关，开启须登记 light-crawler
  预检引用（crawler_precheck_ref）——本包只点名校验，不代行
  crawler 的预检门；PSS 需登录，只作人工复核登记，禁止自动化；
  智慧芽等厂商 API 只登记为可选渠道，启用前须登记披露考量
  确认；EPO OPS 为欧洲侧官方 API 通道，v1 只登记。
- 最小披露构造（query 命令）：检索式只能由分类号 + 手段短语
  构成；构造器拒绝案件标题、整句技术方案、超长短语入查询。
- D1 与三态门：精排池中锁定 D1（须已核验 + 选定理由 + 证据
  级别），逐特征比对产区别特征 Fk（标注每条 Fk 是否对解决
  技术问题有贡献，与 §10 的 6.4 口径对齐）；门结论三态（过 /
  带疑点过 / 不过）落字，不过仍可成文但案件落 degraded 降级
  点名、创造性论述降级。

## §7 P3 撰写

- 权要先行与三箱分拣：独权候选特征逐项分箱——必要特征（缺之
  问题不解或即区别点）进独权；实施例选择进从属；接口细节只
  进说明书。分拣以贡献为准（§10 的 6.4）：对解决技术问题有
  贡献的特征必须写入权利要求，未写入者在创造性评价时不予
  考虑；无贡献特征不许用来凑创造性论述。
- 独权必要技术特征的形式要件见专利法实施细则（2023 年修订）
  第 23 条。从属权要一机制一权项、按价值排序；引用只能指向
  在先权要，多项从属权要不得再作多项引用的基础。概括须有
  说明书实施支撑，薄分支标风险或收窄。载体权要（装置、设备、
  存储介质、程序产品）只能由已有支持的方法特征生成，不许
  空挂。权利要求超过 10 项的部分收附加费（每项 150 元，费减
  另计），登记时由 claims 命令机械算并点名。
- 说明书镜像独权：每条权要特征在支持映射中须有说明书章节或
  源锚点落点；AI 类按 §10 清单逐项落字。摘要不超过 300 字。
  附图标记先登记（numerals），正文引用与登记一致；专利附图
  的生产与审计走 light-figure 的专利档衔接（黑白线稿、无图内
  标题），本包只管标记账。
- 申报副本：strip 命令由工作副本机械剥离 HTML 批注、撰写
  说明/查新过程段与源锚点令牌，生成 draft/filing/ 并做洁净
  检查（过程词表零命中）与哈希 diff 留痕。

## §8 P4 审核（双层）

- 确定性检查器（check 命令）：权要编号连续、单句号、不确定
  词表（等、约、大约、可以、例如、优选、不限于、左右、基本
  等）、引用方向与多项引用规则、先行基础（启发式，WARN 须
  人工复核）、发明名称长度、摘要 300 字、附图标记一致、支持
  覆盖、占位符与缺口对账、AI 充分公开清单、伦理审查登记、
  申报副本洁净。报告落 check/check_report.yaml，含覆盖自报
  （checked / not_checked 两栏）与工件哈希——检查后改稿，
  validate 点名 STALE，须重跑。
- 红队两队（redteam 命令登记）：权要红队以敌意审查员视角攻
  新颖性、创造性（三步法组合）与客体；整包红队攻跨文件一致
  性、哈希与时序、正文洁净。两队各带覆盖自报。双层缺一或
  ERROR 未清：交付等级 incomplete draft。
- 交付分级只两档：deliverable_draft（仍带草案声明）与
  incomplete_draft。禁止任何「可申报」措辞。

## §9 P5 审查意见答复

- 流程：审查意见结构化（逐条缺陷：法条、涉及权要、引证、
  摘要）→ 本申请基线（复用 P2 锁定的 D1/Fk 证据账，不重建）
  → 让步与缺口分析 → 说明书后备特征挖掘 → 候选修改对 D1
  组合重演三步法压力测试 → 修改蓝图 + 答辩蓝图 → 意见陈述
  书草稿（经用户/代理师确认后成稿）。
- 每条修改经 amend 命令落账：修改对象、前后文、出处指针
  （basis_pointer）、出处原文摘录（basis_quote）、第 33 条
  自查确认，四者缺一拒绝（LP-08）。
- 答复期以通知书载明期限为准登记（response_months），台账
  按登记月数机械算到期日，本包不臆定法定期限。

## §10 规范锚点：84 号令关键条文（逐字引用，CNIPA 官方决定原文）

以下引文为局令第 84 号决定原文（2025-11-10 公布，2026-01-01
施行），撰写与判定口径以此为准：

1. 伦理审查（审查指南第二部分第九章第 6.1.1 节，专利法第 5 条
   第 1 款）：「对于包含算法特征或商业规则和方法特征的发明
   专利申请，如果其中的数据采集、标签管理、规则设置、推荐
   决策等含有违反法律、社会公德或者妨害公共利益的内容，则
   根据专利法第五条第一款的规定，不能被授予专利权。」命中
   四个触发面的案件，P0 时先落伦理审查登记再撰写（check 的
   C-12 项）。
2. 充分公开撰写要求（第 6.3.1 节）：「如果涉及人工智能模型
   的构建或者训练，则一般需要在说明书中清楚记载模型必要的
   模块、层级或者连接关系，训练必需的具体步骤、参数等；如果
   涉及在具体领域或者场景中应用人工智能模型或者算法，则
   一般需要在说明书中清楚记载模型或者算法如何与具体领域
   或者场景相结合，算法或者模型的输入、输出数据如何设置以
   表明其内在关联关系等。」check 的 C-11 项按此清单逐项核。
   反面样本为同节例 21：只给数据名目、不给关键指标与因果
   依据，判不符合专利法第 26 条第 3 款。
3. 创造性贡献特征（第二部分第四章第 6.4 节）：「发明对现有
   技术作出贡献的技术特征，例如，使发明产生预料不到的技术
   效果的技术特征，或者体现发明克服技术偏见的技术特征，
   应当写入权利要求中；否则，即使说明书中有记载，评价发明
   的创造性时也不予考虑。对技术问题的解决没有作出贡献的
   特征，即使写入权利要求中，通常也不会对技术方案的创造性
   产生影响。」
4. 比特流（新增第二部分第九章第 7 节）：「如果一项权利要求
   的主题仅仅涉及一种单纯的比特流，则该权利要求属于专利法
   第二十五条第一款第（二）项规定的智力活动的规则和方法，
   不属于专利保护的客体。」由特定视频编码方法限定的存储、
   传输方法与存储介质属技术方案；其权要「一般应当以生成该
   比特流的特定视频编码方法权利要求为基础，通过引用该特定
   视频编码方法权利要求、或者包括该特定视频编码方法全部
   特征的方式撰写」。
5. 发明人资格（第一部分第一章第 4.1.2 节）：「发明人应当是
   个人（即自然人），请求书中应当填写所有发明人的身份信息，
   并确保信息真实。请求书中不得填写单位或者集体，以及人工
   智能名称」；且「不得填写虚假的发明人」。本包只记发明人
   姓名与贡献对应，身份信息线下核对、不落文件（LP-12）。

其余高频锚点：专利法（2020 年修正）第 2 条（客体）、第 22 条
（新颖性/创造性/实用性）、第 25 条（不授予客体，含智力活动
规则方法）、第 26 条（申请文件与充分公开、权要以说明书为
依据）、第 33 条（修改不超范围）、第 35 条（申请日起 3 年内
请求实质审查）。

## §11 P6 台账与 P7 政策雷达 lite

- 台账（ledger.yaml）：期限清单机械算——优先权/PCT 窗（在先
  申请日 + 12 个月，只提示不代办）、请求实审期限（申请日 +
  3 年）、答复期（通知日 + 登记月数）、授权后年费周年；
  版本链记录关键节点工件哈希。提醒靠 light-leader 的 route
  点名本案 status 与 blocked，不建 cron、不承诺通知（Q6）。
- 政策雷达 lite（radar 命令）：条目登记于包内
  radar_entries.yaml，信源分 A 级（官方原文，可支撑口径）与
  B 级（转述线索，不得单独改口径）；只出简报（条目、施行日、
  对交底写法与申请文件写法两栏影响），不自动修改任何技能
  文件——改口径须另行点名走修订。种子条目为 84 号令五项，
  信源为 CNIPA 官网决定原文（A 级）。

## §12 集成契约（LD-02 / MM2-13）

- 案件登记头 case.yaml 顶层含 status，供 light-leader status
  汇总只读消费；blocked 字段与 leader 的 blocked_gate 字段族
  同形，route 在触发条件成立时给提示而非必经下一步。
- ledger.yaml 的 memory_export 段供 light-memory 承接适配器
  直读：案件即对象（patent_case），状态流转与期限即事件，
  查新结论与 worth-it 判断即事实（带证据指针与初筛声明）。
- 与 light-idea 的分工：idea 的 facet 查新判「做不做」，本包
  查新判新颖性/创造性并落 D1 逐特征，证据级别要求更高，两边
  判定口径不互冒。

## §13 诚实边界与交付收尾

- 本包不做的事：不代递交、不代缴费、不签章；不做 FTO/侵权
  的法律意见（只出初筛底稿形态，v1 连底稿形态也只限查新与
  worth-it 结论）；不做专利地图、布局围栏、他人专利解读
  （P7 旁路后置 v1.1）；不承诺任何授权概率。
- 演示与模拟件必须显形标注：演示中的模拟申请号、模拟审查
  意见一律带「演示模拟」字样，不许与真实收据混同。
- 评测集：eval/ 12 个封闭案例（只借 IPBench 分层与
  patent-bench 引证真值形态，数据自建），版本变更后用同批
  案例回归，分数如实记录，不许挑例。
- 交付收尾（X-10）：每次交付报告强制四行——完成项 / 跳过项 /
  未验项 / 风险，逐行落字，不许合并含糊。
