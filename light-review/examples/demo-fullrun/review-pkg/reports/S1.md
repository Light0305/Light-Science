## 总评

本稿的证据结构是单主张（C1）五登记行：R-FIX / R-ORA / R-PRED / R-LONG /
R-NEG。结论包给出的总判定是 support=untested、grade=insufficient，稿件登记
侧 writable_form 已按上限落在 limitations_only——登记纪律本身没有越界，
法医层逐边对账亦未发现登记侧改写。但从方法学看，成稿的证据形态有三处
必须在投稿前正视的问题。

## 主要意见

1. **主张含未检验行而成稿（→ RV-C001，major）**。R-NEG 行因数据版本
   vnext 缺 seg-05/06、支撑 run 出现 fundamental 失败（F-0001），在结论
   包中是 untested 终态。主张 C1 的五分之一证据面从未被检验。稿件登记
   已如实封顶，但摘要与讨论必须保持这一事实可见：读者只看摘要时不应
   得到「方法已被完整评估」的印象。

2. **R-LONG 与 R-PRED 不是两份独立证据（→ RV-C002，major）**。两行的
   处理臂段级分布逐值相同（79.09, 76.642, 79.623, 73.899, 80.589,
   77.169），判定输入哈希一致（62ccc7ade1…）。把五行并列陈述会让读者
   误以为有五份独立支持；稿件应明示 R-LONG 与 R-PRED 同源，或合并陈述。

3. **判读标准（SESOI）只有文本形态（→ RV-C004，minor）**。等价界 ±2 点
   来自合成 design 的文本判读标准，经演示转写件（design-sesoi-source
   .json）进入结论包，Design 登记行本身无结构化 SESOI 字段（回流
   RX-A001 未闭环）。方法节应声明判读标准的来源与冻结时点，否则审稿人
   无法复核 TOST 的界从何而来。
