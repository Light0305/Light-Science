# light-software-copyright SKILL（v1 定版）

> 定位：Light-Science **出口层扩展位**（与 light-patent 并列，位于 review 之后的权利固化出口）。把一个已经定版的软件，变成一套可递交中国版权保护中心的登记材料包：登记事实单源 → 源码冻结快照 → 选材留痕 → 源程序鉴别材料 → 文档鉴别材料（逐段确认）→ 申请表字段派生 → 发布门禁 → 正式资料包 + 逐字段递交清单。**v1 止步于资料包与清单：不代填报官网、不处理签章页、不代用户签署任何声明。**
> 辖区：只做中国软著（Q1）。其他法域的软件登记明确出界，不许拿本包口径套用。
> 产物形态例外：全项目交付物以 MD 为主，但登记材料是法定形态件，本包正式产物为文本材料 + DOCX（Q5 双轨），草稿段与清单为 MD/JSONL 留痕。此为例外及其理由，写死在此。
> v1 定版（2026-10-21）：坐标 SC0–SC7 全落为 CLI 命令与状态机；演示见 examples/demo-fullrun/demo-report.md（自造脱敏小软件走通至 packaged）。

## §1 硬约束（HC，任何情况下不许绕）

- **HC-1 代码真实性**：鉴别材料只能来自 SC0 冻结的真实源码。禁止 AI 编造代码、禁止注水注释/复制虚构代码凑页、禁止改写源码内容；冻结后源码漂移即阻断，须重新冻结。末页不足是合法形态。材料每一行可回溯（文件路径 + 原始行号，见材料索引）。
- **HC-2 单一事实源**：软件全称/简称/版本/著作权人/日期/发表状态只存 facts.yaml 一份。申请表字段、页眉、说明书封面、文件名全部派生；材料侧出现第二份手填真值即结构错误，派生不一致即发布阻断。
- **HC-3 陈述回源码核对**：说明书与申请表中每处功能性陈述必须能回指源码或界面证据。草稿段由 AST 机械抽取的符号作证据指针，无证据的功能段不生成；项目自述与实现冲突时以源码为准。占位符/模板残留（他软件的示例文本、TODO 类）命中即发布阻断。
- **HC-4 AI 声明真实性**：全程保留工具使用记录（tool_use.jsonl，只增不改）。当期申请表声明原文未取得是已登记事实——**本包不保存、不提供、不臆造任何声明措辞**；递交前用户须自备当期原文落案并逐字核对（declaration 门）。技能不得协助用户作与记录不符的声明：回执声称未用工具起草而留痕有起草记录，门判定矛盾并阻断。本包不存在签署动作，签字永远由用户本人在登记系统完成。
- **HC-5 第三方与敏感信息零混入**：第三方/开源代码（权属非申请人的部分）、他人版权标识、密钥与敏感配置不得进入鉴别材料；检出即整份排除并在 selection.json 留痕。**不许删除他人的版权声明来冒充自有**；认为误判走 appeal 归属自证（留痕），不许静默放行。
- **HC-6 人工门禁不可默认跳过**：登记事实、选材、文档草稿段、声明核对四类确认必须有用户显式确认回执（confirmations.jsonl），且确认绑内容指纹——内容一变回执即失效，须重新确认。禁止「未选择则默认继续」。
- **HC-7 规则时效**：规则快照带日期与证据等级（A 规章原文 / B 当期转述 / unobtained 未取得）。被标 dynamic 的字段（主要功能字数、声明文本、上传格式）只警告不硬拦、无当期原文复核不得定版递交。带商业引流的工具仓口径属不可采信级，不进规则快照。

## §2 拍板口径（Q1–Q8，用户 2026-10-21 定版）

- Q1 辖区：中国 only。
- Q2 AI 参与（主开关）= **折中**：工具起草 → 用户逐段确认改写后定版 → 工具使用全程留痕 → 递交前逐字核对当期声明原文（硬门）。**明确不采**：全自动生成 + 以通过 AIGC 检测为目标的改写回路（与 HC-4 方向冲突）；机械分工极（说明书全由用户手写）亦未采。
- Q3 文档形态：按软件类型分流——有界面（gui）走**操作手册**，无界面（headless）走**设计说明书**。由 facts.software.kind 机械决定，不许为页数观感换形态。
- Q4 递交深度：v1 止于正式资料包 + 逐字段递交清单。
- Q5 渲染双轨：源程序材料确定性直接渲染（构造保证页数 + 实测复核兜底）；文档材料走 DOCX 轨，目录页码按文本模型回填并标注口径（真分页以办公套件打开为准）。
- Q6 截图：v1 只做用户截图导入整理（哈希收据）；不自动截图。跳过时留可见预留位（段首登记形态），并在递交清单待补项显形。
- Q7 独立包，不与 light-patent 合并，不抽公共包。
- Q8 页数口径：跟随真实内容（小项目可短）。页数只作实测登记项，**不作目标、不设下限**。唯一硬口径是登记办法第十条：前后各连续 30 页、不足 60 页全交、程序每页不少于 50 行、文档每页不少于 30 行。

## §3 坐标（SC0–SC7）与命令

| 环 | 名称 | 命令 | 产物 |
|---|---|---|---|
| — | 建案 | `init` | copyright.yaml 登记头（顶层 status） |
| SC1 | 登记事实收集 | `set-facts`（导入）→ `confirm-facts` | facts.yaml + 确认回执（绑指纹） |
| SC0 | 软件定版冻结 | `freeze --source` / `verify` | snapshot.json（文件清单+哈希+行数） |
| SC3 | 源码选择 | `select` / `appeal` / `confirm-selection` | selection.json（入选+排除留痕） |
| SC4 | 源程序鉴别材料 | `render-code` | 源程序鉴别材料.txt + index.jsonl + code-manifest.json |
| SC5 | 文档鉴别材料 | `draft-doc` → `revise-segment` / `confirm-segment` → `render-doc`；`import-shot` | draft/segments + 文档材料 txt/docx + doc-manifest.json |
| SC6 | 申请表信息 | 随 check/package 派生 | 字段表（form.derive_application，单一派生函数） |
| SC7 | 递交核对与打包 | `declaration record/verify` → `check` → `package`；`correct` | 资料包/ + 递交清单.md；补正回路 30 日 |

案件目录建议名（项目内）：`软件著作权申请资料/`。状态机：draft → facts_confirmed → frozen → materials_ready → confirmed → release_checked → packaged；旁路 correcting（补正后回 packaged，correction 留痕保留）。

## §4 关键机制口径

- **分页构造（SC4）**：有效行 = 非空源行按显示列折行（全角 2 列，列宽 100，只切分不改字）后的行流；每页 50 行（代码）/30 行（文档，折行列宽 60）；全量超 60 页取前后各连续 30 页，省略页号区间与行数写入 manifest 显形。渲染后 measure 复核页数与逐页行数，构造值与实测值双记，不一致即门失败。
- **逐段确认（SC5/Q2）**：草稿段 SEG-xx.md + segments-manifest.json（带证据指针与段哈希）。confirm-segment 逐段落回执；revise-segment 改写后 manifest 哈希更新、旧回执自动失效。全段确认后状态才进 confirmed，render-doc 才可执行。
- **declaration 门（SC7 硬门）**：三要件缺一不可——(1) 用户自备当期声明原文文件落案（declaration record，注明取得渠道，本包只登记哈希）；(2) 用户本人逐字核对回执（declaration verify，绑原文哈希，原文被改即失效）；(3) 工具使用留痕完整且与回执无矛盾（HC-4 矛盾检）。
- **发布门禁（check）**：事实回执有效 + 快照无漂移 + 选材回执有效且入选非空 + 双材料在案且实测合规 + 页眉与 facts 派生一致 + 逐段确认与证据齐全 + 占位/敏感扫描清零 + declaration 门全过 + 截图哈希无漂移。全过才许 package。
- **补正回路**：correct 登记通知日与事项，期限 = 通知日 + 30 日机械算（登记办法第二十二条）；correcting 中改事实须重走确认链，重新 check + package 回 packaged。

## §5 规则快照（带等级，动态项递交当日复核）

- A 级（规章原文）：鉴别材料前后各连续 30 页/不足全交、程序 50 行每页、文档 30 行每页（第十条）；审查 60 日（第二十条）；补正 30 日（第二十二条）。
- B 级（行业转述，只警告）：主要功能 500–1300 字（深圳市软件行业协会 2026-03-15 转发通知）；上传格式与签章以当期系统为准。
- unobtained（未取得，只建门不造词）：当期申请表 AI 使用声明原文——生态 17 仓与官方公开渠道六路核查均未取得；取得后须回填复核本快照。
- 快照日期随登记头 rules_snapshot_date 登记；过期只警告，不臆测新口径。

## §6 失败模式（见即停，点名上报）

1. 冻结后源码被改 → verify/check 逐个点名漂移文件，停，重新冻结。
2. 材料里出现源码中不存在的功能 → 无证据段，停，删段或补真实实现后重新冻结。
3. 用户要求凑页、删第三方声明、代写/代签声明、把声明原文「凭印象写一个」→ 拒绝并点名对应 HC 条款，给合法替代路径（如 appeal、逐字核对当期表单）。
4. 规则口径只有转述来源 → 按 B 级只警告，或 unobtained 只建门；不许把转述写成法定要求递交。
5. 确认回执失效 → 不许「之前确认过」带过；指出失效对象与原因，重新确认。

## §7 与其他包的关系

- light-leader：出口层扩展位；登记头顶层 status 供 leader status 只读汇总；route 只在「软件已定版」类触发条件给提示，非主流水线必经步。
- light-memory：案件事件（定版、递交、补正、登记号）与版本谱系走 memory 收编（承接适配由集成步统一交付，本包只保证登记头与留痕文件形态稳定）。
- light-patent：同为权利固化出口，共性（事实单源、规则快照、递交门禁、补正回路）各自成文，不抽公共包（Q7）。
- 与 Zotero、Doc2X 无关。
